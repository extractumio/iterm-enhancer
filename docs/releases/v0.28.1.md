# v0.28.1 — The bridge stays connected with no window in focus

## What changes

- **Recovers by itself.** When the focused iTerm2 window closed and no other window took the
  focus (a script's own window, iTerm2 behind another app), the bridge stopped reporting to the
  backend: the Files panels said "Not following iTerm2" and the status showed the bridge not
  connected until a window was clicked. With no terminal pane in focus, the bridge now follows
  the pane it followed last while it is open, else the current pane of any open terminal window,
  so it stays connected as long as a terminal window is open.

## Upgrading

Run `~/.iterm-enhancer/bin/iterm-enhancer upgrade`. Open web app pages reload themselves, and
you stay signed in.

## Validation

Rust, Python and UI unit tests pass, with new tests of which pane the bridge follows (the
focused one, the last one with no window in focus, another window's once that one closed, none
with no terminal window), and the private browser checks pass. The iTerm2 checks in an isolated
iTerm2 pass; checked live: with no window in focus, a restarted bridge was connected within 3 s.

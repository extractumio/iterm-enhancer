# v0.34.0 — Full-screen programs keep their layout in Wrap

## What changes

- **Midnight Commander, vim, top and other full-screen programs keep their rows.** Wrap
  re-flows lines to the browser's width, so in a pane wider than the browser every row of a
  full-screen program broke over two lines and its frame fell apart. While such a program runs
  (iTerm2 shows its alternate screen) in a pane wider than the view, Wrap now shows it as Fit:
  iTerm2's exact layout, scaled to the browser's width. The Wrap button stays selected, and
  Wrap comes back when the program ends. A pane that fits the view stays in Wrap; Grid and Fit
  are unchanged.
- Measured in iTerm2: mc, vim, top, Codex and a plain tmux use the alternate screen; less,
  man, nano and Claude Code do not, so they re-flow as before.
- **Fit no longer shrinks text to 4 px** when the profile reports no font size.

## Upgrading

Run `~/.iterm-enhancer/bin/iterm-enhancer upgrade`. Open web app pages reload themselves, and
you stay signed in.

## Validation

Rust, Python and UI unit tests pass, with a new bridge test of the full-screen flag: sent with
the screen, sent alone when no cell changed, and still sent when iTerm2 changes it while a
frame is on its way. The browser checks pass, with a 200-column full-screen program in a
narrower view (one view row per row, inside the view, Wrap still selected, Wrap back when it
ends) and an 80-column one that stays in Wrap. The iTerm2 integration checks pass with a
private backend in windows of their own; iTerm2's notices of the flag and its value for nine
programs were measured in windows of their own.

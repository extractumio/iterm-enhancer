# v0.29.0 — Bookmarks in the web app, and links that open

## What changes

- **Bookmarks.** In the web app, select text in the terminal and press the orange **+** beside
  it to keep it with a note, to come back later to a part of a coding agent's or a command's
  output. The session's bookmarks are orange marks on the terminal's right edge: press one and
  the page scrolls back to the text and marks it, also when it is in older lines not loaded
  yet, in a folded part of the history or in a rendered Markdown or code widget. A bar shows
  the note, with Edit, Delete and ↑ ↓ to the others. Sessions with bookmarks have an orange
  strip in the session list, and **Bookmarks** below it lists all of them, also those of
  sessions that closed. When the lines are gone from the history, a bookmark shows what was
  selected and the note.
- **Kept on the Mac.** Bookmarks are in `~/.iterm-enhancer/state/web-bookmarks.json`, readable
  only by you, so your phone and your Mac see the same ones, also after a restart. iTerm2
  numbers its history anew when a pane's width changes, so a bookmark is found again by its
  text, near the line it was on.
- **Copy beside a selection.** A gray button above the **+** copies the selected text and keeps
  the selection, so it can be bookmarked too.
- **Links only to files that are there.** A file path the output names is underlined and opens
  only when its file is there (a relative path from the pane's folder). Names printed for
  another folder no longer open View with an error.
- **Held keys.** Holding a key keeps its pace on a slow connection (keys typed while the last
  ones are on their way go to the pane together; a tmux pane on a host took 135 ms a key), a
  held hot key repeats, and a held letter repeats also under macOS's press-and-hold.
- **Selecting in a widget** now pauses the terminal's updates as selecting its text does.

## Upgrading

Run `~/.iterm-enhancer/bin/iterm-enhancer upgrade`. Open web app pages reload themselves, and
you stay signed in.

## Validation

Rust, Python and UI unit tests pass, with new tests of how a bookmark is kept, stamped and
found again (after the history was wrapped anew, by a part of rendered Markdown, nearest its
line, quickly in a long run of one letter) and of the check for files (one listing per folder,
a name printed before a `cd`). The browser checks pass in Chromium and WebKit, among them 25
for bookmarks: the **+** and Copy, the marks, the way back into older, folded and rendered
lines, another pane, gone lines, a refused save, a selection in a widget. The iTerm2 checks
pass in an isolated iTerm2, with a new one in real iTerm2: a bookmark's text moved from line
127 to 254 when the pane narrowed and was found there in 22 ms. Not automated: touch on iOS.

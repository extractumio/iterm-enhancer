# v0.34.3 — Arrow keys in Midnight Commander

## What changes

- **The arrows work in Midnight Commander.** mc switches the terminal to application cursor
  keys and, in a pane outside tmux, took no key at all after the web app's arrow until it was
  restarted. iTerm2 does not tell which mode a program asked for, so while a pane shows a
  full-screen program (mc, vim, htop) the web app now sends the arrows, Home and End the way
  that mode expects. Arrows with Shift, Alt or Ctrl, shells and coding agents are unchanged;
  tmux -CC panes worked already. The menu's "Application cursor keys" switch stays.

## Upgrading

Run `~/.iterm-enhancer/bin/iterm-enhancer upgrade`. Open web app pages reload themselves, and
you stay signed in.

## Validation

Measured in real iTerm2 with programs in windows of their own: mc moves on the new keys and
stopped taking keys after the old ones; vim, nano and htop take both; in a private tmux -CC
both reach mc. Rust, Python and UI unit tests pass. The browser checks pass, with a new one:
on a full-screen program the arrows go in the new form, in a shell as before; it fails
without the fix.

# v0.19.0 — Update notice and steadier panels

## What changes

- **Update notice.** About once a day the bridge asks GitHub which release is the
  latest. When it is newer than the one you run, the panel header shows a small chip
  such as `↑ v0.20.0`. Its menu copies the upgrade command
  (`~/.iterm-filebrowser/bin/iterm-filebrowser upgrade`), skips that release, or stops
  the check. Nothing is downloaded or installed from the panel; upgrades stay signed
  and verified by the command. The request is one `HEAD` to the project's releases page
  with no data of yours; GitHub sees your IP address, as for any request. Builds made
  from a checkout never ask. To switch the check off by hand, create
  `~/.iterm-filebrowser/state/no-update-check`; delete it to check again.
- **A panel that could not bind to its window no longer follows every window.** After
  an iTerm2 restart or an upgrade many panels load at once and their window guesses
  collide. Such a panel took the state of every window, so opening a window or starting
  `screen` re-read the tree of every panel. It now keeps the window it first showed and
  says "Click here to follow this window"; a click binds it. Terminal commands from a
  panel that is not bound are refused, because it may show another window's pane.
- **An upgrade no longer reloads every panel.** A bridge restart inside the same iTerm2
  process does not register the Files tool again while its URL is unchanged, which
  reloaded every panel as a new web view and dropped its window binding.

## Upgrading

Run `~/.iterm-filebrowser/bin/iterm-filebrowser upgrade`. This first upgrade still
reloads open panels once (the build before it has no registration marker), and panels
of windows you do not click in may ask for a click as above. iTerm2 restarts are not
needed.

## Limits

- After an iTerm2 restart with several windows, the panel of the window you switch to
  shows its older pane until you click in it once; a window cannot identify itself to
  its panel (iTerm2 web views report no window and get no focus events).
- The update chip appears only for release builds, and only once a release newer than
  yours exists; builds before v0.19.0 do not check.

## Validation

Rust, Python and UI unit tests, and the private browser checks (200), cover the window
binding, the update chip and its menu, and the check against a local fake of GitHub.
A request against the real releases page returned the latest tag from the Python of the
owner's running bridge and from iTerm2's bundled Pythons. The chip against a real newer
release, and the window behaviour after a restart with several windows, need the
owner's check in iTerm2.

# v0.34.1 — The cursor stays in a coding agent's input

## What changes

- **The cursor no longer jumps below Claude Code's footer.** After a key Claude Code puts the
  terminal's cursor on its caret, but a redraw of its own while it waits (a recap, a status
  line's refresh) leaves it on the row after the footer. The web app drew it there, lost the
  input box (no input panel on a phone) and moved nothing on a tap, ↑ or ↓. It now draws the
  cursor on the caret where it was last seen in the box, or at the end of the input when it
  was not seen, and the next key brings Claude Code's own cursor back.

## Upgrading

Run `~/.iterm-enhancer/bin/iterm-enhancer upgrade`. Open web app pages reload themselves, and
you stay signed in.

## Validation

Measured in a live Claude Code pane through the iTerm2 API: the cursor below the footer while
idle after a recap, on the caret while typing and while it works. Rust, Python and UI unit
tests pass, with new tests of where the caret is drawn. The browser checks pass in Chromium
and WebKit: the cursor left below the footer is drawn on the caret with the box kept, ↑ goes
on from there, and a new theme followed by a frame of the changed rows leaves one cursor; they
fail without the fix.

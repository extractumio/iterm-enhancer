# v0.34.2 — A long input stays a coding agent's input; buttons drawn by hand

## What changes

- **A long input is still the input box.** The web app looked for Claude Code's input box only
  within 12 rows of the cursor, so in a longer input the cursor jumped below the footer again,
  the phone's input panel went away and ↑ and ↓ moved by iTerm's rows. The box is now found
  however long the input is.
- **Also when the input is taller than the screen.** Claude Code then scrolls the input's first
  rows, with its top rule and prompt, up into the history; the web app now finds them there.
  A prompt left in the history by an input sent earlier is not taken for the box.
- **→ at the end of a wrapped row no longer moves the words after it.** In Wrap, → from a
  row's last character puts Claude Code's cursor on the space the row wrapped at; the web app
  drew that cell and a space of its own, so the rest of the line moved right by one. The
  cursor's cell is now that space.
- **Buttons are a little uneven, as drawn by hand.** A rectangular button's top and bottom
  edges bow out or in by a pixel or two, neighbors differently; its border and the keyboard
  focus follow that outline. Scroll to the bottom and View's way back to the terminal are
  blobs. Browsers without CSS `shape()` (Safari before 18.4) keep straight edges. The
  terminal's widgets and the Files and View panes are unchanged.

## Upgrading

Run `~/.iterm-enhancer/bin/iterm-enhancer upgrade`. Open web app pages reload themselves, and
you stay signed in.

## Validation

Measured in real iTerm2 with Claude Code: an input of 40 rows in a 25-row window keeps its top
rule and prompt in the history; those rows give the box, the screen alone none. Every step of
← → (304) and ↑ ↓ through a text with wraps at a space, a word broken at the row's edge, line
ends, a blank line and Cyrillic, at 60 to 151 columns, also in tmux -CC, in Chromium and
WebKit at phone and desktop widths: no character moved on the page, ↑ ↓ kept their column.
Rust, Python and UI unit tests pass, with new tests of long inputs, inputs taller than the
screen and a prompt left far up in the history. The browser checks pass in Chromium and
WebKit: a 19-row input and a 50-row input on a 30-row screen are the box, the cursor left
below the footer is drawn on the caret, ↑ moves a line up, the cursor on a wrap's space moves
nothing, and the buttons are bowed with a ring for a border; each fails without its fix. On
the maintainer's live panes the boxes found are the same as before.

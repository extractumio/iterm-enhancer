# v0.34.2 — A long input stays a coding agent's input

## What changes

- **A long input is still the input box.** The web app looked for Claude Code's input box only
  within 12 rows of the cursor, so in a longer input the cursor jumped below the footer again,
  the phone's input panel went away and ↑ and ↓ moved by iTerm's rows. The box is now found
  however long the input is.
- **Also when the input is taller than the screen.** Claude Code then scrolls the input's first
  rows, with its top rule and prompt, up into the history; the web app now finds them there.
  A prompt left in the history by an input sent earlier is not taken for the box.

## Upgrading

Run `~/.iterm-enhancer/bin/iterm-enhancer upgrade`. Open web app pages reload themselves, and
you stay signed in.

## Validation

Measured in real iTerm2 with Claude Code: an input of 40 rows in a 25-row window keeps its top
rule and prompt in the history; those rows give the box, the screen alone none. Rust, Python
and UI unit tests pass, with new tests of long inputs, inputs taller than the screen and a
prompt left far up in the history. The browser checks pass in Chromium and WebKit: a 19-row
input and a 50-row input on a 30-row screen are the box, the cursor left below the footer is
drawn on the caret and ↑ moves a line up; they fail without the fix. On the maintainer's live
panes the boxes found are the same as before.

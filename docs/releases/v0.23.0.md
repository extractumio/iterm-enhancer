# v0.23.0 — First install starts reliably

## What changes

- **First install with iTerm2 running.** iTerm2 reads its AutoLaunch folder when it starts, so
  right after a first install (or a reinstall after `uninstall`) it could answer "Script not
  found", and the installer wrongly said to turn on the Python API. The installer now asks
  iTerm2 again for up to 15 s; if iTerm2 still has not listed the script, it says to restart
  iTerm2, after which the Files panel starts by itself.

## Upgrading

Run `~/.iterm-enhancer/bin/iterm-enhancer upgrade`. An install of the earlier name
(iterm-filebrowser) is removed with its own `uninstall` first, as described in v0.22.0.

## Validation

Rust, Python and UI unit tests (with new cases for a script iTerm2 lists late, one it never
lists, and refused Automation), and the private browser checks pass. Seen on the owner's Mac:
the v0.22.0 install answered "Script not found" right after iTerm2 restarted, and the same
launch worked once iTerm2 had listed the script.

# v0.28.0 — The web app: output widgets and a compact history

## What changes

- **Code, Markdown and diagrams in the terminal.** In the web app, a file printed with `cat`,
  `bat`, `head`… and fenced code are highlighted; Markdown is rendered, with **Raw / Markdown**
  and **Copy**; a Mermaid diagram is drawn and opens full screen. Output a program colored
  itself (`bat`, `glow`, Claude Code) stays as it is, and the terminal's own text, selection and
  copying are unchanged. Works under two-line prompts with a clock, such as Starship's, and on
  a document a coding agent's tool printed (indented, as its tools' output is).
- **Images named in the output.** An image file the output names gets a button after it, but
  only once the file is known to be there. It opens centered below its line, at most half the
  terminal's width and height; a click opens it full screen.
- **Full-screen viewer.** Pinch, scroll or drag to zoom and move, double-click for 1:1, Esc to
  close.
- **A compact history, before it is sent.** The bridge folds a pane's history into one line
  each, with **Show** and **Copy**: a coding agent's edit diffs, long commands and long tool
  output, rows of base64 or hex, long runs of nearly equal lines (a file listing), and an input
  box redrawn into the history. Folded lines are sent only when you press Show. On the owner's
  panes this sends 45% less history, and 93% less for a 5,000-line file listing. The live
  screen is never folded.
- **Long chats stay fast.** Widgets are drawn only near the part of the history you look at,
  and the view no longer jumps when a widget, an image or a diagram appears or when you type in
  a coding agent's input box.

## Upgrading

Run `~/.iterm-enhancer/bin/iterm-enhancer upgrade`. Open web app pages reload themselves, and
you stay signed in. The first diagram you open loads Mermaid (about 3.6 MB) once; the browser
keeps it.

## Validation

Rust, Python and UI unit tests pass, with new tests of what becomes a widget (and what does
not: program comments, YAML, colored output), of the bridge's folds (diffs, commands, output,
data, listings loaded in pages, a cleared scrollback, which lines a page may ask for), and the
private browser checks in Chromium and WebKit: widgets drawn in place and within the screen,
the reader's place kept, folds shown and copied, no CSP violation. The owner's demo window was
replayed through the page at desktop and phone sizes; rendering was checked in the iOS 26.3
Simulator's Safari; load and typing were measured on a 10,000-line chat against the previous
release.

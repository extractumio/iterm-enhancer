# v0.18.0 — Automatic terminal recovery

File Browser now saves terminal layouts automatically and reconstructs missing
terminals after a reboot or an unclean iTerm2 exit. Saving and recovery are enabled
by default; no manual checkpoint or setup checkbox is required.

## What changes

- Save all windows, ordered tabs and nested splits, including inactive/minimized
  panes, with working directories, window frames and terminal dimensions.
- Wait for iTerm2's native restoration, adopt identified live panes and restore
  missing terminals. Busy panes and user changes remain intact.
- Skip File Browser's automatic reconstruction after an observed, durably recorded
  normal iTerm2 exit such as Command-Q, when reopening in the same macOS boot.
  A reboot still enables recovery. Automatic saving and manual Restore stay available.
- Exclude observed ordinary shell exits and explicit pane/tab/window closes from
  all retained recovery sources. Restored shells close on completion without a
  Restart prompt; failed connection attempts keep their diagnostics and Retry.
- Reconnect supported SSH sessions with interactive authentication and restore
  trustworthy remote directories. Reattach verified surviving tmux servers;
  rebuild lost local servers with shells, saved layouts and directories only.
- Show shared recovery progress, checkpoint history, deviations and
  **Retry / reconcile** in the Files panel. An automatic-saving opt-out persists.
- Reuse iTerm2's **Command-Shift-O — Open Quickly** for session navigation; type
  `/f` to search open sessions. The panel also has **Find terminal session**.
  Command-Shift-T retains iTerm2's existing **Undo Close** action.
- Configure system window restoration, native session restoration and automatic
  shell integration for supported profiles during installation. Report settings
  only when changed; show setup failures separately and defer setup if iTerm2 is stopped.
- Remove closed-window caches after 60 seconds of confirmed absence and inactive
  Files workspaces after 14 days. Live inactive panes are retained; inventory gaps
  pause cleanup. Recovery history is bounded to 64 snapshots and 128 MiB.

This release also includes the security and data integrity fixes merged from
`origin/main`: stricter viewer handoff validation, remote-response deadlines,
verified helper updates and Files editing/navigation regressions. Release notes
are now kept in the repository and published through the signed release workflow.

## Failure handling

Bridge/backend restarts and upgrades in the same iTerm2 process do not repeat a
completed restoration. Delayed startup and interrupted recovery retain their
durable source before capture begins; partial attempts can be reconciled without
replaying commands into existing panes. Corrupt state and unsupported connections
produce explicit reports.

Missing or inaccessible directories fall back to home or `/` with a warning;
the restorer does not recreate removed directories. Failed controlled connections
keep their source available for Retry and the next iTerm2 launch. Remote directory
targets are retained while authentication or shell metadata is unavailable.

## Limits

- Claude, Codex and other previously running applications are not relaunched.
  A reboot cannot preserve their process memory; shell startup files and native
  iTerm2 restoration may independently start programs.
- iTerm2/macOS window reopening is independent of the plugin's normal-quit policy.
  **Command-Option-Q — Quit and Close All Windows** can discard native saved windows.
  Normal exit status does not identify the initiator, so orderly app updates and
  same-boot logout can also skip automatic reconstruction.
- Closure or Quit during a bridge outage, or before durable acknowledgement,
  cannot be distinguished reliably from failure. Periodic capture can miss
  changes made immediately before shutdown or while the bridge is unavailable.
- Lost remote tmux servers require manual recovery. Remote/control-mode attachment,
  real reboot, interactive SSH authentication and exact display/Spaces/fullscreen
  placement still require owner validation.
- Files editor/tree state is not migrated to newly assigned terminal IDs.

## Validation

Rust, Python and UI unit tests and private browser checks cover normal operation,
failures and state durability. Owned iTerm2 fixtures verify a 15-window layout,
tabs/splits, directories/frames, partial retries, normal shell exits and simulated
process/boot transitions. Private tmux and generated SSH failure fixtures exercise
recovery without reading credentials or touching the installed state.

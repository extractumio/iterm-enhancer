# v0.27.0 — The web app: no CPU spin, faster typing, a latency trace

## What changes

- **No more slow waves.** With web access on, the bridge could sit at 100% CPU for minutes and
  iTerm2's requests timed out (the panel's poll, recovery checkpoints): a request without a body
  left an empty part in the socket's buffer, and Python's event loop wrote 0 bytes over and over
  for as long as a Files panel's event stream stayed open. Writes now leave empty parts out.
  This had been there since web access came in 0.23.0.
- **Typing is not held up by the session list.** The list's poll asked iTerm2 for everything at
  once, and a key queued behind it. The poll now has at most 4 requests in flight and waits
  while you type: key to echo went from 30–36 ms to 10–11 ms (median) against a busy iTerm2.
- **One page reads the screen.** On a computer, a page out of focus now pauses like a hidden
  one, so a page left open on the Mac reads no screens while you use the iPad.
- **Subagents under their agent.** A coding agent's subagents in panes of its tab show under
  the first pane, shifted in, each with its own title (they were six rows with the tab's title
  and "pane n of 6"). A filter shows them flat.
- **⌘C and ⌘V with a hardware keyboard** on a phone or a tablet: ⌘C copies the selected
  terminal text, and after a copy the keyboard field takes the keys back, so ⌘V pastes into
  the pane.
- **Latency trace.** When typing lags, open the page with `?trace=1`. For 15 minutes the page
  and the bridge record how long each key takes to its echo and where (page, connection,
  bridge, iTerm2 or tmux), sessions opened, round trips and stalls, into
  `~/.iterm-enhancer/logs/trace-*.jsonl`; no typed text or screen content. A badge shows the
  time left and the echo. `scripts/trace_report.py` sums it up. When the bridge itself is busy,
  `kill -USR1 <bridge pid>` writes its busiest functions over 15 s to a `profile-*.txt` there.

## Upgrading

Run `~/.iterm-enhancer/bin/iterm-enhancer upgrade`. Open web app pages reload themselves, and
you stay signed in.

## Validation

Rust, Python and UI unit tests and the private browser checks pass, with new checks of the
trace (records keep only known names and numbers, a key joined to the frame where the cursor
moved, the 15-minute and 20 MB limits), the poll's limit and its wait while typing, socket
writes without empty parts, child panes, a page out of focus, and copy and paste with a
hardware keyboard. The iTerm2 checks in an isolated iTerm2 pass. The CPU spin was found by
profiling the running bridge and is reproduced by a test on a real socket; typing was timed
against a live iTerm2 with all its windows polled; ⌘C/⌘V was checked in the iOS 26.3
Simulator with a hardware keyboard.

# v0.20.0 — Session Window Recovery, a tidier panel, clearer install output

## What changes

- **Session Window Recovery.** The recovery dialog (the clock button in the Files header)
  has a clear title, an × button and two parts: **Automatic saving** (the switch, and
  **Save a new checkpoint now**, which adds a checkpoint and changes no other) and
  **Restore** (the checkpoint list and **Restore selected**).
- **The newest checkpoint is selected.** The dialog used to preselect the previous iTerm2
  run's last stable checkpoint. It now selects the newest checkpoint with a window, unless
  startup recovery is pending or a restore did not finish.
- **A short checkpoint list.** Intermediate checkpoints saved while you rearrange windows
  are hidden; the list shows checkpoints that stayed unchanged for 30 s and the newest of
  each run, grouped under "This iTerm2 run" and "Earlier iTerm2 runs", labeled like
  `Today 12:44:37 · 2 windows, 8 panes · latest`. Nothing is deleted on disk.
- **Header and footer.** The mode badge (`BASH`, `TMUX`, …) sits left of the path on the
  second line; the pane's process note (`pid …, running …`) moved to a footer.
- **Install output.** A successful install or upgrade ends with a green check where the
  terminal takes colors; the PATH tip follows a blank line, in gray, and is not shown when
  a shell startup file already adds `~/.iterm-filebrowser/bin`.
- **`iterm-filebrowser status`** prints `panels: N connected, M iTerm2 windows`. iTerm2
  keeps the hidden panels of earlier tool registrations until it quits; when panels
  outnumber windows, quitting iTerm2 frees them.

## Memory

Reported 160–260 MB WebKit processes were measured: thousands of panel events and
hundreds of tab, dialog and menu cycles leave the panel's DOM flat and its script heap
within a few hundred kilobytes; the same processes shrank to 40–90 MB later by themselves.
The real cost is the count of hidden panels, which `status` now shows.

## Upgrading

Run `~/.iterm-filebrowser/bin/iterm-filebrowser upgrade`. Open panels reload by
themselves; no iTerm2 restart is needed.

## Validation

Rust, Python and UI unit tests and the private browser checks (204) cover the dialog,
the checkpoint list and selection, the header and footer, the install output and the
status line. The memory measurement ran in Chromium, not in iTerm2's WebKit.

# v0.24.0 — The web app on a phone: select, copy, rename, open

## What changes

- **Long press and Copy on iPhone.** In Safari a long press on terminal text selects it and
  shows Copy, also with thousands of lines of history, which used to freeze the page for
  seconds. With the keyboard up, a finger held still for half a second closes the keyboard and
  selects the word under it, and the word stays in place. While text is selected, a Copy button
  appears beside the keyboard button. Copied text keeps its line ends, in Wrap and in Grid.
- **Wrap reads like the program wrote it.** Prose that an agent wrapped at iTerm's width is
  joined again on a narrow screen. Tool lines, ⎿ results, list items and numbered code or diff
  lines always start a new line.
- **Paste images.** An image pasted in the web app is saved where the pane's shell runs (this
  Mac, or a host with the helper enabled), and its path is typed into the pane.
- **New tabs and names.** [+] on a group of the session list opens a new tab with the window's
  profile, or a new window of a tmux session. The pencil renames a tab, a session, a tmux
  window or a pane title.
- **Agents at a glance.** Rows of panes running Claude Code or Codex show whether the agent is
  working, waiting for you, failed or done.
- **Links and paths.** Web addresses and file paths in the terminal open on click or tap:
  addresses in a new tab, paths in File.
- **A dropped tmux integration.** When iTerm2 drops a tmux -CC integration while tmux keeps
  sending, the raw protocol stops within seconds, tmux keeps running, and you can reattach with
  one action, on the Mac or in the web app.
- **Steadier on a phone.** A phone keeps about 2000 lines on the page while it follows the
  output; older lines load again when you scroll up. Showing Files or File clears a terminal
  selection, so the terminal no longer stays paused behind them. The "Paused while you select"
  notice no longer covers the view tabs. An open page of an older build reloads itself after
  an upgrade, but never over unsaved edits.
- **Clearer errors.** A failed action is named in words instead of iTerm2's raw error, and a
  pane that has closed no longer blocks opening the next one.

## Upgrading

Run `~/.iterm-enhancer/bin/iterm-enhancer upgrade`. Open web app pages reload themselves.

## Validation

Rust, Python and UI unit tests, the private browser checks (including new checks of the web
terminal's history blocks and its Copy button in WebKit and Chromium), and the isolated iTerm2
checks pass; their tmux -CC latency case was skipped (iTerm2 opened no integration window). The iPhone behavior was reproduced and checked in the iOS Simulator with its
on-screen keyboard: a long press on 3000 lines of history shows Copy, a tap on the selection
no longer freezes the page (7.4 s before), and the Copy button copies the selected word.

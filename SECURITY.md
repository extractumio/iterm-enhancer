# Security

`fbd` gives a web view read and write access to your files, so it is built to be reachable
only by the Files panel:

| Threat | Defense |
|---|---|
| Other machines | binds `127.0.0.1` only |
| Web pages in any browser (CSRF, DNS rebinding) | random 128-bit token (file mode 0600) on every request; exact `Host` check; writes need `Content-Type: application/json` and a same-origin or absent `Origin`; the panels' event WebSocket needs the exact panel `Origin` (a missing one is refused); no CORS headers |
| Local processes of other users | everything under `~/.iterm-filebrowser` is private (folder 0700, files 0600); the bridge and the installer talk to fbd only through a Unix socket there, never over TCP, so a program that takes port 47821 while fbd is not running gets neither the bridge secret nor terminal commands |
| A program on fbd's port (fbd not running: login, an upgrade, a crash) | before a panel sends its token it asks fbd to prove it knows it (HMAC-SHA256 of a fresh nonce): another program cannot, so it never sees the token; a token that may have reached it is replaced (fbd could not get its port, or iTerm2 was just started); fbd restarts at once after a crash. Left: a panel opened or reloaded exactly while another program holds the port loads that program's page |
| The panel page itself (a malicious README or SVG) | Markdown raw HTML disabled, `javascript:` links dropped, remote images not loaded, CSP `script-src 'self'`, SVG only through `<img>`, `Referrer-Policy: no-referrer`, links never navigate the panel; only regular files are read (a link to `/dev/zero` or a FIFO is refused at once) |
| Writes outside your files | writes only under `FB_WRITABLE_ROOTS` (`$HOME:/tmp`), symlinks resolved; deletion moves to the Trash; writable roots and their ancestors must not be renamed or replaced by an untrusted account during an operation (descriptor-relative confinement remains open) |
| The viewer window's URL (visible in its address bar) | holds a one-time code, valid 60 s, traded once for the token only on an exact unexpired code match; never the token itself |
| A forged error toast | bridge errors arrive only through `/internal/error` with the per-launch bridge secret; the text is capped at 300 characters, control characters are dropped, and the panel shows it as plain text |
| Preference edits through the panel | setup consumes only a private, install-scoped request with a unique ID; it reads/writes the three requested preference groups and narrowly selected profile properties. The panel has no preference-edit endpoint. Setup notices and authoritative inventories require the bridge secret on the private socket. |
| Stale terminal identities | only complete inventories start absence grace; API gaps reset it. Expired window state, claims and watcher references are removed together; a missing-window query never borrows another pane. |
| Terminal checkpoints | separate private, versioned metadata; no output, exit codes, history, environment or arbitrary application argv. Strict schema and 4 MiB snapshot limit; immutable generations and journals use fsync, rename and parent fsync. Retired GUIDs exclude observed closures from retained sources (16,384 IDs, 4 MiB index); GC retains only referenced IDs. Root exit evidence stays in memory. History is bounded, current job source pinned; corrupt manifests/journals are preserved and writes refused. |
| Restore duplication or changed live panes | one global durable job per checkpoint, creation-time profile markers, journal GUIDs and exact native IDs; duplicate identities and changed topology stop that operation. Busy/changed panes are preserved. A fresh pre-creation inventory reduces native reopening races; public creation cannot be transactional, so a narrow late-reopening race remains. |
| Relaunching old jobs | Automatic startup and explicit Retry launch controlled shells or generated connection commands, override profile command/initial text/triggers, and never call the unsafe ended-session restart API. Lost local tmux uses private sockets and empty configuration. Existing shell startup, SSH config and native iTerm2 restoration remain independently executable. |
| Startup races and upgrades | Reserve the latest durable source before capture; complete only a journal belonging to the current boot/iTerm2 process. Pending recovery blocks capture; same-process upgrades preserve completed startup. Unsupported storage versions fail closed. Fresh PID/controlling-TTY proof rejects reused PIDs; unknown liveness never supplies cwd/argv or permits mutation. |
| Normal application exit | Exact PID/start proof arms a kernel exit watch; only observed normal status zero records a current-epoch marker over the authenticated private socket. No raw status is persisted. Same-boot startup skips reconstruction but waits for native layout to settle before capture; a new boot overrides the marker. Stale events, signal/nonzero/missing status, denied enrollment and failed persistence cannot suppress crash recovery. Native reopening is never closed by the plugin. |
| SSH recovery | narrow destination/options allowlist excludes arbitrary remote commands and executable overrides; generated quoted remote cwd bootstrap, `RemoteCommand=none`, `PermitLocalCommand=no`. New SSH processes cannot inherit another connection's stale cwd. Authentication occurs in the new terminal, without injected text. No credential/config file contents are captured. |
| tmux recovery | surviving local identity checks PID/kernel start plus session ID/creation; remote checks host/socket/PID/start/session over a read-only strict-host-key, batch SSH probe and repeats it after authentication. Helpers/attachments use `-N` to forbid unexpected server startup; only explicit private initial creation loads empty config. Unverified remote servers are unresolved, never rebuilt. Private local reconstruction checks session/window/pane markers, cwd/jobs/layout before partial retry and preserves user changes. |
| A remote host's agent | runs as the user you ssh in as, writes only under that user's `$HOME` and `/tmp`, listens only on a Unix socket in a private (0700) folder with a random name, accepts only a token given per connection on ssh's stdin, and exits when that connection closes |
| Requests for a remote host | sent only to that host's agent (never to a local file), through a socket in the app folder that only fbd uses; the panel's Origin and token are not forwarded; answers are capped at 64 MB; connection/response headers have a 30 s deadline, finite bodies a 120 s total deadline and 30 s idle deadline, event streams a 30 s idle deadline; lagged streams reconcile through a host-scoped rescan; Finder actions are refused |
| ssh | the same ssh command the tmux session was started with, your own ssh config, `BatchMode=yes` (no password or host-key prompts); helper platform names are restricted to the four packaged targets, copies use unique staging paths and verify the installed build; a host gets the helper only after you click Enable for it (or run `iterm-filebrowser hosts enable`) |
| The installer | `install.sh` downloads into a temporary folder and runs nothing until `SHA256SUMS` is signed by the release key it carries and the package's SHA256 matches; it refuses root; `iterm-filebrowser upgrade` checks with the key of the installed build; `upgrade` refuses archive members other than plain files and folders and strips setuid bits (the bootstrap installer extracts the signed archive with system tar); the signed list names its release, so an older one is not installed as the latest. The first `curl … \| sh` trusts the key in the `install.sh` it downloads (from the same release as the package), so it protects against a swapped package, not against someone who can replace all release files; every later upgrade checks with the key already installed |
| Releases | built and signed on the maintainer's Mac only from a clean tree at `main`, with dependencies exactly as locked (`npm ci --ignore-scripts`, `cargo --locked`); a new version must be above every earlier one; nothing becomes public before the signature (the tag, then a draft release published once complete); a published release is never changed. The key's passphrase is in the maintainer's login Keychain so a release needs no prompt: the key is loaded into ssh-agent for at most two minutes and removed after signing, but a program running as the maintainer while the Keychain is unlocked could load it too |
| The update check | the only network request the program makes by itself: the bridge (not fbd, not the panel, whose CSP allows no remote host) sends one `HEAD` request to the project's GitHub releases page about once a day, with a fixed `User-Agent` and no cookies or data of yours; GitHub sees your IP address, as for any request. Only a tag of the form `vMAJOR.MINOR.PATCH` is kept, shown as text, and compared with the running release; a build from a checkout never asks. Nothing is downloaded or installed: the panel offers to copy the command you run yourself, and `iterm-filebrowser upgrade` checks the signature (above). The chip's menu turns the check off (`~/.iterm-filebrowser/state/no-update-check`; delete the file to turn it on) |
| The CI runner (public repository) | workflows never run for pull requests (fork pull requests also need the owner's approval); every job is read-only, with no token for the GitHub API, so code on the runner cannot change a release; actions pinned to commits |
| Typing into the wrong terminal | terminal commands need a per-launch bridge secret inside fbd, the key of the pane the panel shows, and an idle shell for `cd`; fbd never sends Enter (the user runs the line); iTerm2 broadcast input is suppressed; names are quoted for the pane's own shell (fish differs from bash and zsh) or refused when a shell cannot take them safely; control, bidi and zero-width characters are refused, by fbd and again by the bridge; a name starting with `-` is typed as `./-name` |
| Acting on the wrong machine | a confirmation answered after the panel switched to another host does nothing; a document always saves to the host it came from; a tmux -CC pane whose gateway runs ssh is remote, whatever host name its server reports (a gateway over mosh or et that reports this Mac's host name is still taken for local) |

Report a vulnerability privately through the repository's security advisories
("Report a vulnerability"), not in a public issue. Include the version (`git rev-parse
HEAD`), macOS and iTerm2 versions, and the smallest reproduction.
